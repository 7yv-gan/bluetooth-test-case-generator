# 测试用例规范（编号 / 优先级 / 模板）

生成、扩展、评审用例时遵循本规范，保证用例集在企业内可追溯、可评审、可复用。

## 1. 用例编号规则

```
TC-{模块码}-{类型码}-{三位序号}
示例：TC-PAIR-SEC-002
```

**模块码**（用例归属的功能模块）：

| 码 | 模块 | 码 | 模块 |
|---|---|---|---|
| SCAN | 扫描/发现 | DATA | 数据传输 |
| PAIR | 配对/绑定 | MULTI | 多连接 |
| CONN | 连接 | SEC | 安全 |
| DISC | 断开 | PERF | 性能 |
| RECON | 重连 | COMPAT | 兼容 |

**类型码**（用例的测试类型）：

| 码 | 类型 | 码 | 类型 |
|---|---|---|---|
| FUN | 功能 | SEC | 安全 |
| BND | 边界 | PERF | 性能 |
| EXC | 异常 | COMPAT | 兼容 |
| CON | 并发 | EXP | 体验 |

序号从 001 起三位递增；同模块同类型的用例按"先正例后反例"排序。

## 2. 优先级定义

| 优先级 | 含义 | 判定标准 |
|---|---|---|
| P0 | 发布阻断 | 核心主流程（配对-连接-传输）、用户高频路径、安全合规问题；不过则不能发布 |
| P1 | 高 | 重要功能、常见异常场景；缺陷影响多数用户 |
| P2 | 中 | 次要功能、边界场景；缺陷影响部分用户或可临时规避 |
| P3 | 低 | 低频体验问题、极致边界、兼容性深水区 |

优先级分布建议：P0 约占 10–20%，P1 约占 30–40%，其余为 P2/P3。

## 3. 用例字段模板

每条用例必须包含以下字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| 用例ID | 是 | 按编号规则生成，全局唯一 |
| 标题 | 是 | 一句话说明验证的行为，如"配对成功后自动重连" |
| 优先级 | 是 | P0/P1/P2/P3 |
| 测试类型 | 是 | FUN/BND/EXC/CON/SEC/PERF/COMPAT/EXP |
| 模块 | 是 | 所属模块码 |
| 前置条件 | 是 | 环境、设备状态、数据准备，可执行 |
| 测试数据 | 否 | 需要的外部输入/参数 |
| 测试步骤 | 是 | 编号列表，每一步可操作、无歧义 |
| 预期结果 | 是 | 与步骤对应，可明确判定通过/失败 |
| 备注 | 否 | 关联需求、缺陷号、风险说明 |

## 4. 用例质量标准（评审用）

1. **单一验证点**：一条用例只验证一个行为，避免一用例多断言
2. **可操作性**：步骤精确到可执行的粒度，第三方测试员可照做
3. **可判定性**：预期结果必须可明确判定通过与失败，不用"正常""合理"等模糊词
4. **可追溯**：编号唯一、模块/类型归属清晰，可回溯到需求或缺陷
5. **正反结合**：每个需求点至少一条正例 + 关键反例（错误参数/异常状态）
6. **独立执行**：用例之间不互相依赖，可单独执行与统计

## 5. 完整示例（P0 级）

```
用例ID：TC-PAIR-FUN-001
标题：使用 Passkey Entry 完成配对并绑定
优先级：P0
测试类型：FUN
模块：PAIR
前置条件：1) 手机与目标设备均支持蓝牙；2) 目标设备可被发现；3) 手机定位权限已开启
测试数据：PIN=123456
测试步骤：
  1. 打开手机蓝牙，进入"添加设备"页面开始扫描
  2. 在扫描结果中选择目标设备发起配对
  3. 当手机弹出 PIN 输入框时，输入 123456 并确认
  4. 等待配对完成
  5. 断开连接后再次连接
预期结果：
  1. 扫描列表中显示目标设备名称与信号强度
  2. 手机与设备进入配对流程，出现 PIN 输入框
  3. 配对成功，设备出现在"已配对设备"列表
  4. 应用内显示"已连接"状态
  5. 无需重新配对即可直接连接（绑定生效）
备注：关联需求 BLE-REQ-012
```
