# 蓝牙连接领域知识（生成测试用例的领域依据）

本文件提供生成蓝牙连接测试用例所需的领域事实。生成用例前先阅读，确保测试点覆盖真实的技术行为和典型缺陷模式。

## 1. 两种蓝牙技术对比

| 维度 | 经典蓝牙 BR/EDR | 低功耗蓝牙 BLE |
|---|---|---|
| 典型用途 | 耳机、音箱、车载、键鼠（HFP/A2DP/AVRCP/SPP 等 profile） | 手环、传感器、防丢器、遥控器（GATT 架构） |
| 连接模型 | 建立 RFCOMM 逻辑信道，profile 协商 | GATT Server/Client，Service/Characteristic |
| 配对 | 传统配对 + SSP（Secure Simple Pairing） | LE Legacy / LE Secure Connections |
| 关注指标 | 音质、语音链路稳定性 | 功耗、时延、吞吐（MTU/ATT） |

**测试含义**：先确定被测设备是经典蓝牙还是 BLE，选择对应的连接流程与测试点。

## 2. 连接生命周期状态机

```
Idle → Scan/Inquiry（发现）→ Discoverable（可被发现）→ Pairing/Bonding（配对/绑定）
     → Connecting（连接中）→ Connected（已连接）→ Data Transfer（数据传输）
     → Disconnecting（断开中）→ Disconnected（已断开）
     └── 任一步失败进入 Failed/Timeout，需回退或重试
```

**测试含义**：每个状态转换节点都是一个测试点；每个节点的失败处理（超时、重试、回退）都要覆盖。

## 3. 配对与绑定方式

- **Just Works**：无用户确认，安全性最低，用于无输入输出能力的设备
- **Numeric Comparison**：双方显示 6 位数字，用户确认一致（防 MITM）
- **Passkey Entry**：一方显示、一方输入 PIN（键盘/屏幕设备）
- **OOB（Out-of-Band）**：通过 NFC 等带外信道交换密钥
- **Bonding（绑定）**：配对后持久化密钥，下次自动连接；解除配对=删除绑定密钥

**测试含义**：不同配对方式有不同交互步骤和失败路径；绑定丢失是重连失败的典型根因。

## 4. BLE GATT 要点

- 连接建立后通过 GATT 发现 Service/Characteristic 才能收发数据
- Characteristic 支持 Read / Write / Notify / Indicate
- 连接参数（Connection Interval、Slave Latency、Supervision Timeout）影响功耗与时延
- MTU 协商影响单包传输大小

**测试含义**：数据传输用例需要区分"连接成功"与"数据通道可用"是两个验证点。

## 5. 地址与隐私

- 设备地址分公共地址与随机地址；随机地址又分静态、私有可解析（RPA）、私有不可解析
- 开启隐私模式后设备地址周期性变化，依赖 bonding 的 IRK 才能识别

**测试含义**：地址变化场景下，重连依赖绑定密钥而非固定地址——这是重连测试的关键场景。

## 6. 典型缺陷模式（测试重点来源）

| 缺陷现象 | 常见根因 | 测试关注点 |
|---|---|---|
| 扫描不到设备 | 广播停止、过滤条件、定位权限未开、协议栈异常 | 扫描开关、权限、过滤、重启恢复 |
| 连接失败/超时 | 距离过远、射频干扰、对端忙、超时参数过短 | 超时边界、重试次数、失败提示 |
| 偶发掉线 | 连接参数不当、低电量、系统省电策略、固件 bug | 长时间稳定性、低电量、省电模式 |
| 配对失败 | PIN 错误、安全策略不一致、重复配对冲突 | 各配对方式、错误 PIN、重复配对 |
| 重连失败 | bonding 丢失、地址隐私变化、缓存陈旧 | 重连流程、解除绑定后、隐私地址 |
| 多设备冲突 | 连接数上限、角色切换、广播冲突 | 连接数上限、多设备并发 |
| 数据传输丢包/卡顿 | MTU 协商失败、流控不足、干扰 | 吞吐、可靠性、断点续传 |
